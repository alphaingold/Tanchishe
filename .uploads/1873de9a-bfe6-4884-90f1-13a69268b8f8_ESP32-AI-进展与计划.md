# ESP32-S3 + DeepSeek 入门项目 · 进展与计划

> 用途：换电脑迁移用。本文档记录了已完成的全部步骤、必须对齐的软件环境、可用的完整代码，以及后续学习提纲。
>
> 最后更新：2026-11-26

---

## 一、项目概述

用一块 **ESP32-S3-N16R8** 开发板，接一个电位器，把读数通过 WiFi 发给 **DeepSeek API**，让大模型做判断，再按模型返回的 JSON 控制板载 RGB 灯。

目标不是做产品，而是**把"AI 能上网、能读传感器、能控制硬件"这条链路走通一遍**，理解大模型在嵌入式里到底能干什么、不能干什么。

核心认知（已通过实验确认）：

- 大模型**不测量物理量**，它只看你给它的**文字**。同样的读数 3000，说成"电位器读数"和说成"电池电量"，它的回答会不一样。
- 模型输出要能被程序使用，必须**用提示词强制它输出固定格式（JSON）**，并加 `temperature = 0` 压制发挥。
- AI 真正不可替代的价值是：**规则可以用自然语言改，不用重新编译上传**。

## 二、硬件清单与接线

### 2.1 硬件

| 物品 | 型号/参数 | 备注 |
| --- | --- | --- |
| 开发板 | ESP32-S3-N16R8 | 16MB Flash + 8MB PSRAM，双 Type-C 口 |
| 电位器 | 10K 旋转电位器（三针） | 接面包板 |
| 面包板 + 公母线 | 若干 | 电位器占第 1/2/3 列 |
| 板载 RGB 灯 | WS2812，GPIO48 | 无需接线，代码直接控制 |

### 2.2 两个 Type-C 口的区别（重要）

| 口 | 电脑识别名 | 用途 |
| --- | --- | --- |
| CH340 口 | `USB-SERIAL CH340 (COM7)` | **当前用这个**，上传和串口监视都走它 |
| 原生 USB 口 | `USB 串行设备 (COM4)` | 备用，不用 |

> **端口号会随插拔变化（COM7 可能变成 COM8），认名字 `USB-SERIAL CH340`，不要死认编号。**
> 如果新电脑上不显示 CH340，需要装 CH340 驱动（见第五章）。

### 2.3 电位器接线（已验证，读数 0→4095 连续变化）

| 电位器针脚 | 接到 ESP32-S3 |
| --- | --- |
| VCC | 左排顶部 `3V3` |
| GND | 右排靠 USB 处 `GND` |
| AO（中间针） | 右排第 3 个针 `1`（即 **GPIO1**，ADC1_CH0） |

电位器三针插在面包板**第 1/2/3 列**。

### 2.4 板载 RGB 灯

不需要接线。ESP32-S3 开发板板载 WS2812，引脚 **GPIO48**（已实测能亮）。少数老批次是 GPIO38，如果上电自检不闪，把代码里的 `RGB_PIN` 改成 38 再试。

**不能用 `digitalWrite` 控制**，必须用 ESP32 Arduino core 3.x 自带的：

```cpp
rgbLedWrite(RGB_PIN, R, G, B);   // 每个颜色 0-255
```

## 四、Arduino IDE 全局配置（必须逐项对齐，错一项就编译失败或反复重启）

打开 **工具（Tools）** 菜单，逐项设置：

| 菜单项 | 必须选 |
| --- | --- |
| 开发板（Board） | **ESP32S3 Dev Module** |
| 端口（Port） | `USB-SERIAL CH340` 对应的 COM 口（今天是 COM7） |
| USB CDC On Boot | **Disabled** |
| Flash Mode | **QIO 80MHz** |
| Flash Size | **16MB (128Mb)** |
| PSRAM | **OPI PSRAM** |
| 分区方案（Partition Scheme） | **16M Flash (3MB APP/9.9MB FATFS)** |
| 上传速度（Upload Speed） | **921600**（失败就降到 115200） |

### 三个致命配置坑（已踩过）

1. **Flash Mode 选成 OPI 80MHz** → 编译报 `sdkconfig.h` 相关错误，或烧进去后 `RTCWDT` 反复重启。
2. **ArduinoJson 用 6.x** → 请求 DeepSeek 返回 **HTTP 400**。
3. **USB CDC On Boot 设成 Enabled** → 串口监视器看不到输出（走的不是同一个串口）。

### 步骤 1：装 Arduino IDE

到 arduino.cc 下载 **Arduino IDE 2.x Windows 版**，默认安装即可。

### 步骤 2：添加 ESP32 开发板地址

`文件 → 首选项 → 附加开发板管理器网址`，填入：

```
https://espressif.github.io/arduino-esp32/package_esp32_index.json
```

### 步骤 3：装 ESP32 板包

`工具 → 开发板 → 开发板管理器`，搜索 `esp32`，选 **Espressif Systems** 的，**版本选 3.3.12**，安装。
（首次安装会下载几百 MB，慢是正常的，建议挂代理或用国内镜像。）

### 步骤 4：装库

`工具 → 管理库`，搜索 `ArduinoJson`，选 **Benoit Blanchon** 的，**装 7.x 版本**。

### 步骤 5：装 CH340 驱动（如果新电脑认不出串口）

插上板子的 CH340 口，看 `设备管理器 → 端口`：

- 显示 `USB-SERIAL CH340 (COMx)` → 已就绪，跳到步骤 6。
- 显示黄色感叹号 / 未知设备 → 搜 `CH340 驱动`（沁恒 WCH 官网），装完重新插拔。

### 步骤 6：选板子和配置

按**第四章**的表格逐项设置。板子选 `ESP32S3 Dev Module`。

### 步骤 7：复制代码

本文档**第六、七章**有两个版本的完整代码，直接复制到 Arduino IDE。

需要你手动填两处（本文档里是占位符）：

```cpp
const char* WIFI_PASS = "你的WiFi密码";
const char* API_KEY   = "你的DeepSeekKey";
```

> API Key 自己去 platform.deepseek.com 后台复制。**不要把 Key 写进本文档，也不要上传到 GitHub。**

### 步骤 8：编译验证

点左上角 **→ 上传**。看到 `Done uploading` / `Hard resetting via RTS pin` 即成功。

### 步骤 9：串口监视器

右上角打开串口监视器，波特率 **115200**，**换行符必须选 NL**（选错就读不到你输入的规则）。

## 六、已完成章节与验证记录

### 6.1 板子自检

打印芯片型号、Flash 大小、PSRAM 大小。确认是 **ESP32-S3 / 16MB / 8MB**。

### 6.2 WiFi 连通

连接 `qqaa`，拿到 IP **192.168.237.75**（会变），请求 HTTP 返回 **200**。

### 6.3 串口对话

模型 `deepseek-chat`，提示词约束"回答 50 字以内"。串口需选换行符 **NL**。

### 6.4 电位器读数

`analogRead(GPIO1)`，设 `analogReadResolution(12)`，实测 **0 → 4095 连续变化**，接线可靠。

### 6.5 电位器 → AI 判断

把读数拼成中文问句发给 AI，AI 返回一句人话建议。

两个省 token 的限制（后面一直沿用）：

- `CHANGE_THRESHOLD = 150`：读数变化超过 150 才发请求。
- `MIN_INTERVAL`：两次请求的最小间隔（最初 8000ms，后来降到 3000ms 方便实验）。

### 6.6 JSON 闭环控灯（今天跑通的最终版本）★

**状态：已上传、已实测通过。**

实测日志：

```
电位器读数：4095，开始询问 AI...
AI 原文：{"level":"high","action":"on"}
>>> 灯已点亮（红）

电位器读数：1798，开始询问 AI...
AI 原文：{"level":"low","action":"off"}
>>> 灯已熄灭
```

**关键实现点：**

- 提示词里写死"≥2048 为 high"，并**强制只输出 JSON**，不要解释、不要 markdown。
- `temperature = 0` 让输出稳定。
- 解析时先取 `choices[0].message.content`，再**截取第一个 `{` 到最后一个 `}`** 之间的内容（防止 AI 偶尔包一层 ` ```json `）。
- `action == "on"` → `rgbLedWrite(RGB_PIN, 120, 0, 0)` 亮红；否则 `rgbLedWrite(RGB_PIN, 0, 0, 0)` 熄灭。
- `setup()` 里有一段**上电自检：闪一下红光再灭**，用来确认引脚正确。

**完整代码：**

```cpp
#include <WiFi.h>
#include <HTTPClient.h>
#include <WiFiClientSecure.h>
#include <ArduinoJson.h>

// ===== 第 1 块：配置区 =====
const char* WIFI_SSID = "qqaa";
const char* WIFI_PASS = "你的WiFi密码";
const char* API_KEY   = "你的DeepSeekKey";

const int POT_PIN = 1;   // 电位器 AO -> GPIO1
const int RGB_PIN = 48;  // 板载 RGB 灯（不闪就改 38）

const int CHANGE_THRESHOLD = 150;        // 读数变化超过 150 才问 AI
const unsigned long MIN_INTERVAL = 8000; // 两次询问至少隔 8 秒

int lastSent = -1;
unsigned long lastTime = 0;

// ===== 第 2、3 块：问 AI + 解析 JSON + 控制灯 =====
void askAIAndControl(int value) {
  WiFiClientSecure client;
  client.setInsecure();
  HTTPClient http;
  http.begin(client, "https://api.deepseek.com/chat/completions");
  http.addHeader("Content-Type", "application/json");
  http.addHeader("Authorization", String("Bearer ") + API_KEY);
  http.setTimeout(20000);

  // 提示词：强制只输出 JSON
  String prompt = "你是设备控制助手。电位器读数范围 0 到 4095。";
  prompt += "读数大于等于 2048 判定为 high，否则为 low。";
  prompt += "严格只输出一个 JSON 对象，不要解释，不要 markdown 代码块。";
  prompt += "格式为 {\"level\":\"high\",\"action\":\"on\"}，";
  prompt += "high 时 action 为 on，low 时 action 为 off。";
  prompt += "当前读数：";
  prompt += value;

  JsonDocument req;
  req["model"] = "deepseek-chat";
  req["messages"][0]["role"] = "user";
  req["messages"][0]["content"] = prompt;
  req["temperature"] = 0;

  String body;
  serializeJson(req, body);

  int code = http.POST(body);
  if (code != 200) {
    Serial.printf("请求失败，HTTP %d\n", code);
    http.end();
    return;
  }

  String payload = http.getString();
  http.end();

  JsonDocument resp;
  if (deserializeJson(resp, payload) != DeserializationError::Ok) {
    Serial.println("返回内容不是合法 JSON");
    return;
  }
  String content = resp["choices"][0]["message"]["content"].as<String>();
  content.trim();
  Serial.print("AI 原文：");
  Serial.println(content);

  // 只截取第一个 { 到最后一个 } 之间
  int s = content.indexOf('{');
  int e = content.lastIndexOf('}');
  if (s < 0 || e <= s) {
    Serial.println("AI 没按格式返回，本次跳过");
    return;
  }
  content = content.substring(s, e + 1);

  JsonDocument cmd;
  if (deserializeJson(cmd, content) != DeserializationError::Ok) {
    Serial.println("解析 JSON 失败，本次跳过");
    return;
  }
  String action = cmd["action"] | "off";
  if (action == "on") {
    rgbLedWrite(RGB_PIN, 255, 0, 0);   // 亮红灯
    Serial.println(">>> 灯已点亮（红）");
  } else {
    rgbLedWrite(RGB_PIN, 0, 0, 0);     // 熄灭
    Serial.println(">>> 灯已熄灭");
  }
}

// ===== 第 4 块：主循环 =====
void loop() {
  int value = analogRead(POT_PIN);
  unsigned long now = millis();

  bool changed = abs(value - lastSent) >= CHANGE_THRESHOLD;
  bool timeUp  = (now - lastTime) >= MIN_INTERVAL;

  if (changed && timeUp) {
    Serial.printf("\n电位器读数：%d，开始询问 AI...\n", value);
    askAIAndControl(value);
    lastSent = value;
    lastTime = now;
  }
  delay(50);
}

void setup() {
  Serial.begin(115200);
  delay(500);

  // 板载灯自检：闪一下红光
  rgbLedWrite(RGB_PIN, 50, 0, 0);
  delay(400);
  rgbLedWrite(RGB_PIN, 0, 0, 0);

  analogReadResolution(12);   // 0-4095

  Serial.print("正在连接 WiFi");
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }
  Serial.println();
  Serial.print("WiFi 已连接，IP：");
  Serial.println(WiFi.localIP());
  Serial.println("转动电位器：>=2048 应亮红，<2048 应熄灭");
}
```

## 七、待验证章节：自然语言改规则（代码已给出，尚未上传）★ 明天从这里开始

**状态：代码已发，用户未上传、未验证。**

和 6.6 的区别只有两处：

1. 把提示词里写死的"≥2048 为 high"删掉，换成变量 `userRule`，由你在串口里输入。
2. 新增 `checkSerialCommand()`，读串口整行，存成新规则，并把 `lastSent` / `lastTime` 归零，让它**立刻生效**。
3. `MIN_INTERVAL` 从 8000 降到 3000，方便反复试规则。

**操作方式：**

1. 上传后打开串口监视器（115200 + NL）。
2. 在底部输入框打字，例如 `超过3000才开灯，否则关灯`，按回车。
3. 串口打印"规则已更新"，随后立刻打印 AI 原文和灯的响应。

```cpp
#include <WiFi.h>

// ===== 新增块：读取串口里你输入的规则 =====
void checkSerialCommand() {
  if (!Serial.available()) return;

  String line = Serial.readStringUntil('\n');
  line.trim();
  if (line.length() == 0) return;

  userRule = line;
  Serial.println();
  Serial.print(">>> 规则已更新为：");
  Serial.println(userRule);
  Serial.println(">>> 马上用当前读数验证一次");

  Serial.print("正在连接 WiFi");
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }
  Serial.println();
  Serial.println("WiFi 已连接");
  Serial.print("当前规则：");
  Serial.println(userRule);
  Serial.println("在下面输入框写新规则，按回车发送，例如：超过3000才开灯");
}
```

**这一节要验证的两件事：**

1. AI 有没有老实按你输入的新规则判断。
2. **规则与读数冲突时判得对不对**——例：规则改成"超过3000才开灯"，当前读数 1500，它应该返回 `off`。

**可试的规则语句：**

- `超过3000才开灯，否则关灯`
- `读数在1000到3000之间开灯，太亮或太暗都关灯`
- `超过2500开灯，但不要闪烁`

## 八、踩坑记录与排错速查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 编译报 `sdkconfig.h` 错误 / `RTCWDT` 反复重启 | Flash Mode 选了 OPI 80MHz | 改回 **QIO 80MHz** |
| 请求 DeepSeek 返回 **HTTP 400** | ArduinoJson 装了 6.x | 换 **7.x** |
| 串口监视器一片空白 | USB CDC On Boot 设成 Enabled | 改为 **Disabled** |
| 串口没输出、也上传不了 | 选错端口 / 插了原生 USB 口 | 选 `USB-SERIAL CH340`，插 CH340 口 |
| 输入规则没反应 | 换行符不是 NL | 串口监视器右下角改 **NL** |
| 上传失败 | 速度太高 | 921600 降到 **115200** |
| 上电灯不闪 | RGB 引脚不是 48 | 改 **38** 重试 |
| 编译报 `rgbLedWrite was not declared` | 板包低于 3.x | 升级到 **3.3.12** |
| 转动电位器不出日志 | 变化没超 150 或没到间隔 | 转到底停 3 秒以上 |
| WiFi 连不上 | 用了 5GHz 或密码错 | ESP32 只支持 **2.4GHz** |

## 九、后续学习提纲

### 第一站：自然语言改规则（第七章，明天开始）

- 上传代码，串口输入规则，验证 AI 是否按新规则判断。
- 故意试一条模糊规则（如"太亮就关"），体会 AI 猜不准的边界。

### 第二站：一句话控制多个输出

- 让 AI 一次返回多个动作，例如 `{"level":"high","actions":["led","fan"]}`。
- 代码里解析数组，分别控制灯和第二个输出（可再用一个 GPIO 接蜂鸣器或第二个 LED）。
- 学到：JSON 数组解析、多设备状态管理。

### 第三站：多传感器综合判断

- 增加 DHT11 / DHT22 温湿度模块（**需确认套件里有没有**）。
- 把温度、湿度、电位器值一起塞进提示词，让 AI 综合判断。
- 学到：多输入数据拼接、提示词变长后 token 成本与响应速度的变化。

### 第四站：亮度与颜色渐变

- 把 0-4095 映射成 0-255 的亮度，做呼吸灯；或从蓝到红渐变。
- 学到：PWM / RGB 混色、`map()` 函数。

### 第五站：规则掉电保存

- 把 `userRule` 存进 **NVS（Preferences 库）**，重启后不用重新输入。
- 学到：Flash 存储、Preferences API。

### 第六站：本地 Web 配置页（可选）

- ESP32 开一个 HTTP 服务，手机浏览器打开网页输入规则。
- 学到：`WebServer` 库、局域网访问。

### 第七站：离线语音唤醒（难度最高）

- 需要改用 **VS Code + ESP-IDF 插件**，环境要重搭。
- 用乐鑫官方 `esp-sr` 做唤醒词"嗨，乐鑫"。

### 第八站：TinyML（可选）

- Edge Impulse 训练一个简单的关键词/手势模型，跑在板子上。
- 学到：模型转换、内存限制。
